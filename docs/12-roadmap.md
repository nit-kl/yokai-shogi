# 12. 開発ロードマップ

このドキュメントは、実装済みの状態と今後の開発候補を整理する。過去の完了チェックリストは残さず、現時点の判断に必要な情報だけを置く。

## 現状

- TypeScript / Vite / shared エンジン / CI は導入済み。
- Cloudflare Workers + Hono + D1 + Durable Objects によるサーバー権威のメタ進行・オンライン対戦は実装済み。
- staging / production の Worker API、D1、Pages 構成は `server/wrangler.jsonc` と `.github/workflows/ci.yml` が正本。
- main push のCIは、本番D1マイグレーション → Worker API → Pages の順にデプロイする。
- クライアントは API 接続時にサーバー権威で動作し、API未設定または接続不能時はローカルメタへフォールバックする。
- 初回オンボーディング、大将選択、10連ガチャ、編成、ログインボーナス、引き継ぎコード、利用同意、Sentry任意初期化、メンテナンス表示は実装済み。
- ランダムマッチは毎日20:00-22:00(JST)に集約し、フレンドマッチはルームコードで常時利用できる。
- 逢魔が時参加報酬、土曜対戦会の限定妖怪、百鬼夜行週間連勝ランキングは実装済み。
- **Steam 配信方針は確定**(本体無料・全駒解放DLC・異装DLC・広告なし・Web 並行クロスプレイ)。実装は未着手。doc 23。

## 次の開発候補

優先度は実ユーザーの動きと運用負荷、および Steam 準備状況で決める。

1. **運用の安定化**
   - Sentry DSN、UptimeRobot、Cloudflareダッシュボード、Analytics Engine の監視を継続運用に乗せる。
   - `docs/analytics-queries.md` のクエリで登録、オンボーディング、対戦、ランキングの実績を定期確認する。

2. **対戦継続性の改善**
   - ランダムマッチの参加導線、待機中の案内、対戦会告知を改善する。
   - 過疎時はソロ・ランキング・対戦会へ自然に誘導する。

3. **長期継続要素**
   - レーティング、シーズン、称号、編成プリセット、妖力の追加用途を検討する。
   - ガチャ天井や未所持優先排出は、所持率データを見てから判断する。

4. **コンテンツ追加**
   - `client/public/assets/pieces/stock/` に候補画像を保管し、採用時に `shared/data.ts`、画像の小サイズ、ガチャプール、テストを更新する。
   - 新妖怪は2-4体単位で追加し、既存の採用率・勝率を見ながら調整する。

5. **リワード広告の本番有効化**(doc 22) — Web のみ
   - コードは実装済み。本番は `ADS_REWARD_ENABLED=0` が既定。
   - Google Ad Manager の Rewarded ユニット開設後、`ADS_REWARD_PROVIDER=gpt` とユニットパスを設定して有効化する。
   - Steam ビルドには載せない(doc 23)。

6. **リプレイ・観戦**
   - `matches` / `match_actions` には対局ログを保存済み。リプレイ画面はイベント列の順再生として実装できる。
   - ライブ観戦は、利用者規模が増えてから検討する。

7. **Phase Steam**(doc 23)
   - 前提: アセット権利棚卸し・商標調査(doc 11)。
   - Tauri シェル、`PLATFORM` 分岐、Steam Auth、同一 Matchmaker への接続、全駒解放 entitlement、ストア提出。
   - 公開後に異装 DLC 第1弾。

## 縮小・停止基準

- ランダムマッチが成立しない状態が続く場合は、フレンドマッチとソロランキングを主導線に寄せる。
- サーバー維持が運用コストに見合わない場合は、オンライン機能を縮小し、ソロ静的版 / Steam オフラインビルドを残す。
- **有償ガチャチケットは導入しない**。ガチャチケットはログインボーナス、勝利報酬、参加報酬、リワード広告(Web)、運営配布で扱う。Steam の有料要素は全駒解放・異装等DLCに限定する(doc 08 / 23)。
