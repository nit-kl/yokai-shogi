# 18. ランダムマッチ流動性戦略

## 目的

少ない月間利用者を広い時間帯へ分散させず、対戦したい利用者を同じ時間へ集める。
短期目標は「ランダムマッチ参加者の70%以上が30秒以内に成立」。達成できない時間帯は
20秒後のAI対戦導線で待機損失を抑える。

この施策ではレート帯、地域、ルールによるキュー分割を行わない。分割は各区分の
同時待機人数が継続的に十分になってから検討する。

## 基本戦略

### 1. 毎日の推奨対戦時間を固定する

- 日本時間の20:00〜22:00を「逢魔が時」として全媒体で統一して案内する。
- タイトル画面、公式X、Discord、Webサイトで同じ名称・時間を使う。
- 広告は常時配信せず、原則として19:30〜21:30へ寄せる。
- KPIは時間帯別の `queue_join`、30秒以内成立率、成立待機時間p50/p90で比較する。

初期値は20:00〜22:00とし、2週間分の実績で最も参加が多い連続2時間へ変更する。
曜日別に十分な母数が得られるまでは曜日ごとに時間を変えない。

### 2. 週1回の公式対戦会を運用する

毎週土曜21:00〜22:00を公式対戦会とする。運営者も一般アカウントでキューへ参加し、
開始15分前と開始時にXで告知する。告知文にはURL、開催時間、登録不要、無料、
ブラウザですぐ遊べることを含める。

運用手順:

1. 当日20:45に本番のヘルスチェックと異なる2アカウントでの成立確認を行う。
2. 20:45に予告、21:00に開始、21:30に途中経過を投稿する。
3. 障害時は募集を止め、フレンドマッチまたはソロ対戦へ誘導する。
4. 翌日に参加数、成立率、待機時間、完走率を記録する。

**勝敗**に紐づく対戦会限定報酬は設けない(勝ち譲り・複数アカウント対策)。代わりに
**参加(完走)報酬**を実装済み(2026-07-04): ランダムマッチを1局完走(10アクション以上)すると
勝敗不問でチケット+1(1日1回)、土曜対戦会はチケット+2に加えて**限定妖怪
「百鬼夜行・ぬらりひょん」を確定入手**(ガチャ排出から除外。初回のみ)。
1日1回上限+最低アクション数により、複数アカウントで空回ししても旨味がほぼない。
実装: `shared/match-hour.ts`(設定値)・`server/src/do/battle-room.ts`(付与)・
`participation_logs`(1日1回の担保)。称号・結果紹介などの非通貨系動機も引き続き併用する。

### 3. 告知と広告を同じ時間へ集中させる

- Xの固定投稿に「毎日20〜22時は対戦が集まりやすい」と明記する。
- 動画・広告のCTAは単なる「今すぐ遊ぶ」ではなく「20時からオンライン対戦」とする。
- 配信者へ依頼する場合も同じ時間帯に公開・配信してもらう。
- UTMに `campaign=match_hour`、`content` に媒体・投稿種別を設定する。
- 流入数だけでなく、キャンペーン時間中の `queue_join` 増分を成果とする。

少額広告を一日中薄く配信すると同時接続を作れないため行わない。予算の増額判断は、
クリック単価ではなく「追加キュー参加者あたり費用」と30秒以内成立率で行う。

### 4. Discordを対戦集合場所として運用する

Discordの目的は雑談コミュニティの規模を増やすことではなく、対戦希望者へ同じ時刻に
キューへ入る理由を作ることである。参加者数ではなく、Discord経由のキュー参加と成立を成果とする。

サーバーを新規作成する具体的な操作は
[Discordサーバー作成・運用手順](19-discord-server-setup.md)に従う。

#### サーバー構成

初期はチャンネルを増やしすぎず、次の構成に限定する。

| チャンネル | 権限・用途 |
|---|---|
| `#はじめに` | 読み取り専用。ルール、ゲームURL、毎日20〜22時の案内 |
| `#お知らせ` | 運営のみ投稿。対戦会、障害、更新情報 |
| `#対戦募集` | 対戦希望時刻の調整とフレンドコード交換 |
| `#攻略・編成` | 対戦後も参加者が残るための攻略情報交換 |
| `#感想・不具合報告` | 定型フォーマットによるフィードバック受付 |
| `#運営ログ` | 運営・モデレーター限定。対応記録 |

ボイスチャンネル、対戦レート別チャンネル、初心者・上級者別募集は初期には作らない。
会話と対戦者を分散させないためである。

ロールは `運営`、`モデレーター`、希望者が自分で取得する `対戦会通知` の3種類から始める。
全員への通知は障害などの重要連絡に限定し、定例対戦会は `対戦会通知` のみメンションする。

#### 対戦募集フロー

ランダムマッチへ人数を集める場合、個別にすぐキューへ入らせず、5分単位の開始時刻を決める。

1. 希望者が `#対戦募集` に「21:15 ランダム参加」のように投稿する。
2. 参加者はリアクションで参加意思を示す。
3. 2人以上集まったら投稿者またはモデレーターが開始1分前に通知する。
4. 全員が指定時刻にランダムマッチへ入る。
5. 30秒で成立しない場合は一度待機を継続し、AI切替は各自が判断する。

特定の相手と遊ぶ場合はランダムキューを使わず、スレッド内でフレンドコードを交換する。
ランダム募集とフレンド募集を投稿冒頭の `[ランダム]` / `[フレンド]` で区別する。

募集テンプレート:

```text
[ランダム] 21:15開始 / 参加できる方は⚔️で反応してください
ゲーム: https://yokai-shogi.nit-games.com/?utm_source=discord&utm_medium=community&utm_campaign=match_hour
```

#### 公式対戦会での運用

- Discordイベントを原則3日前に作成し、日時とゲームURLを固定する。
- 当日20:45に `対戦会通知` へ一度だけ予告し、21:00に開始を通知する。
- 開催中は15分ごとに次の同時参加時刻を案内する。過度な連投はしない。
- Xの告知からDiscordへ誘導する場合も、Discord参加を必須にせずゲームへ直接参加できるリンクを併記する。
- 終了時に次回日時と短いアンケートを投稿する。

#### 新規参加者の定着

- `#はじめに` の最初の画面だけでゲーム開始と対戦会通知ロール取得を完了できるようにする。
- 初回参加者に自己紹介を要求しない。発言せず通知だけ受け取る参加を許容する。
- 初心者向けの固定投稿に基本ルール、ソロ練習、AI切替の説明を置く。
- 対戦結果のスクリーンショット投稿や週次の好局紹介を行うが、敗者名や戦績を本人の同意なく掲載しない。

#### モデレーション

`#はじめに` に、暴言・嫌がらせ・スパム・不正行為の勧誘・個人情報投稿を禁止すると明記する。
違反対応は「投稿削除と注意 → 一時的な書き込み制限 → 退出」の順を基本とし、重大な場合は即時退出とする。
対応日時、対象、理由、措置を `#運営ログ` に残す。ゲーム内のBANとは証拠を確認して別々に判断する。

未成年を含む可能性を前提に、DMでの個別サポートは行わず公開チャンネルで対応する。
ユーザーから受け取る不具合情報に認証トークン、引き継ぎコード、個人情報を投稿しないよう案内する。

#### Discord KPI

招待URLとゲームURLはDiscord専用UTMを使用し、毎週次を確認する。

- Discord招待ページ到達数と新規参加者数
- `対戦会通知` ロール取得数
- 公式イベントの参加予定数と実参加反応数
- Discord告知後30分の `queue_join` 数
- Discord経由ゲーム流入からキュー参加までの転換率
- 募集投稿数、成立報告数、モデレーション件数

メンバー数が増えてもキュー参加が増えなければ成功とは判断しない。通知への反応が低下した場合は
通知回数を増やさず、開催時間、告知文、参加手順を見直す。

### 5. ゲーム内で時間帯を認知させる

段階的に次の表示を追加する。

1. タイトル画面に「逢魔が時 毎日20:00〜22:00」を固定表示する。
2. 開催中はオンライン対戦ボタンへ「対戦相手が集まりやすい時間」と表示する。
3. 開催外にランダムマッチを選んだ場合も参加を妨げず、推奨時間だけ補足する。
4. 実測できるまでは「現在○人待機」などの人数表示をしない。誤差や少人数表示が逆効果になる。

プッシュ通知やメール通知は、同意管理と解除導線が必要になるため初期施策には含めない。

## 実行計画

### 第1週: ベースライン

- キュー計測を本番へ反映する。
- 推奨時間を告知せず7日間計測し、時間帯別参加数を確認する。
- 異常な `disconnect` / `invalid` / `match_failed` があれば集客前に修正する。
- Discordのチャンネル、ルール、通知ロール、専用UTMを準備する。一般募集はまだ行わない。

### 第2〜3週: 時間帯集約

- 毎日20:00〜22:00の告知を開始する。
- 土曜の公式対戦会を2回実施する。
- Discordで5分単位の対戦募集と対戦会通知を開始する。
- 通常時間、逢魔が時、公式対戦会を別々に集計する。

### 第4週: 判断

次の基準で継続方針を決める。

| 指標 | 継続・拡大 | 要改善 | 縮小判断 |
|---|---:|---:|---:|
| 30秒以内成立率 | 70%以上 | 40〜69% | 40%未満 |
| 成立待機時間p50 | 15秒以下 | 16〜30秒 | 30秒超 |
| AI切替率 | 20%未満 | 20〜40% | 40%超 |
| 対戦会のキュー参加者 | 前回比維持・増加 | 横ばい | 2回連続減少 |

- 継続・拡大: 対戦会を週2回まで増やし、集中時間だけ広告予算を増やす。
- 要改善: 最も参加が多い1時間へさらに集中し、告知文と導線を改善する。
- 縮小判断: 常設ランダムマッチを残しつつフレンド募集とAI戦を主導線にする。

## ダッシュボードと定例確認

`docs/analytics-queries.md` のクエリを使い、毎週次を記録する。

- キュー参加ユーザー数と重複を含む参加回数
- 成立率、30秒以内成立率、待機時間p50/p90
- 退出理由別件数（取消、AI切替、切断、無効）
- `match_found` から `match_end` までの完走率
- 時間帯別・キャンペーン別の参加数
- Discord告知後30分のキュー参加数と、募集投稿に対する成立報告数

推奨時間の変更、広告増額、報酬追加は同時に行わない。原則1週間に一つだけ変更し、
変更前後を比較できる状態を維持する。
