# 01. プロダクト要件定義

## ビジョン

「将棋の駆け引き × 駒取りで魂力を削るバトルの爽快感」を、まずブラウザで、将来は Steam でも届ける対戦ゲームにする。
妖怪のコレクション(ガチャ・編成)は**遊ぶだけで完走できる**健全な収集体験を軸にする。勝敗の主因は所持ではなく盤上の読みと編成であり、課金は強さの直売にしない。

運営収入の経路:
- **Web**: 任意のリワード広告など(doc 22)
- **Steam**(計画): 本体無料・広告なし。全駒解放DLC(収集時短)と異装等の見た目DLC(doc 23)

## ターゲットユーザー

| セグメント | 特徴 | 訴求ポイント |
|---|---|---|
| カジュアル対戦ゲーマー | 1局5〜10分の短時間対戦を好む | 5×6の小盤面・テンポの良い演出 |
| 将棋・ボドゲ好き | 戦略性を重視 | 妨/爆など駒の駆け引き、編成の構築深度 |
| コレクション勢 | 図鑑埋め・キャラ収集が動機 | プレイだけで完走可能。急ぐ人は Steam の全駒解放DLCで時短可 |
| Steam / デスクトップ勢 | 起動の手軽さ・ストア発見性 | 無料本体、広告なし、Web とのクロスプレイ |

## 機能スコープ

### 現状

- ソロ対戦(百鬼夜行)、ガチャ、編成、ログインボーナス、勝利報酬、オンライン対戦、ランキング、パスキー、日英UI、初回オンボーディングを実装済み

### 維持する主要機能

- **アカウント**: ゲストで即プレイ開始 → パスキーまたは引き継ぎコードで機種変更・複数端末対応
- **オンライン対戦**: ルームコードでのフレンドマッチ、いつでも可能なランダムマッチ(逢魔が時は推奨時間)
- **サーバー権威化**: ガチャ・チケット・編成・対戦結果をサーバーで管理(改ざん対策)
- **持ち時間制**: 1手60秒+切れ後30秒秒読み(秒読み切れで自動投了)
- **切断・再接続**: 猶予時間内の復帰を許容

### リリース後の拡張(Should / Could)

- レーティング(ランクマッチ)・シーズン制
- 戦績・リプレイ閲覧(対局の棋譜保存)
- 観戦機能、フレンドリスト
- 新妖怪の継続配信
- PWA対応(ホーム画面追加・オフライン時はソロのみ)
- **Steam 配信**(本体無料・全駒解放DLC・異装DLC・Web 並行クロスプレイ)。詳細は doc 23

### 非スコープ(やらないこと)

- **有償ガチャチケット・有償ガチャ・強駒のバラ売り**(Pay-to-Win に見える単体販売)
- Steam 上のリワード広告・AdSense 等の広告 SDK
- モバイルアプリストア向けネイティブ配信(当面)。Steam デスクトップはスコープ内(doc 23)
- チャット機能(定型スタンプのみ検討。自由入力はモデレーションコストが高いため見送り)

### Web と Steam の役割分担

| | Web | Steam(計画) |
|---|---|---|
| 価格 | 無料 | 本体無料 |
| 広告 | 任意リワード可(doc 22) | 出さない |
| 有料要素 | なし | 全駒解放DLC・異装等DLC |
| オンライン | あり | あり(Web と同一マッチプール) |
| 進行データ | D1 メタ | 同一アカウント基盤へ連携 |

## ユーザーストーリー(主要)

1. 初めて訪れたユーザーは、登録なしで30秒以内にAI戦を開始できる
2. プレイヤーはルームコードを友人に送り、ブラウザだけで対戦できる
3. プレイヤーはパスキーまたは引き継ぎコードで、どの端末からでも同じ所持妖怪・編成・チケットを使える
4. 対戦中に回線が切れても、猶予時間内に再接続すれば対局を続行できる
5. ガチャの排出率はゲーム内からいつでも確認できる
6. Steam プレイヤーは無料でソロ/オンラインを開始でき、希望すれば全駒解放DLCでコレクションを時短できる
7. Web と Steam のプレイヤーは同じルール・同じマッチプールで対戦できる

## KPI(リリース後の観測指標)

| 指標 | 目標値(初期) | 備考 |
|---|---|---|
| D1リテンション | 25%以上 | ログボ設計の効果測定 |
| D7リテンション | 10%以上 | 7日連続ログボ(3枚)との相関を見る |
| マッチング成立時間 | 中央値30秒以内 | 過疎時間帯はAI戦へ誘導 |
| 対局完走率 | 90%以上 | 切断・放置の検知。低い場合はペナルティ設計を見直す |
| ガチャ参加率 | DAUの60%以上 | チケット配布量の調整指標 |

## 非機能要件

| 項目 | 要件 |
|---|---|
| 応答性 | 着手送信→相手画面反映まで p95 < 500ms(国内) |
| 同時接続 | 無料枠内で運用し、利用増加時にPaidプランと負荷試験を再検討する |
| 可用性 | 99%(個人運用の現実値。メンテ告知の仕組みを用意) |
| データ保全 | DBは日次バックアップ+ポイントインタイムリカバリ(可能なら) |
| 対応環境 | Web: 直近2年の Chrome / Safari / Edge / Firefox、iOS / Android のモバイルブラウザ。Steam: Windows を必須、Steam Deck 検証を推奨(doc 23) |
| アクセシビリティ | 色弱対応(タイプ識別を色+ラベル文字で冗長化 ※現状実装済みの方針を維持) |

## リリース判定基準(Go/No-Go)

オンライン公開済み。以下は継続運用の健全性チェックとして維持する。

- [ ] 全自動テスト(エンジン・スキル・メタ・UI・プロトコル)がグリーン
- [ ] staging/productionの接続スモークテストで、着手遅延・完走率に重大な問題がない
- [ ] チート検証: クライアント改ざんでチケット・勝敗・ガチャ結果を操作できないことを確認
- [ ] 利用規約・プライバシーポリシー・ガチャ排出率の掲示
- [ ] 障害時のロールバック手順・告知手段の整備
